# 开发路线图

以下均为待实现或待补齐项，不代表已排期或已验收。项目继续围绕财报研究中的证据获取、计算与核验展开。

## 开放服务前

- 认证、会话归属与资源授权：验证跨用户读取、停止和删除均被拒绝。
- 财报数据使用与外发边界：明确来源许可、允许发送给模型的字段、数据与追踪保留策略。
- 结构化证据和确定性校验：将数值、期间、单位、来源与公式绑定，程序校验引用存在性和复算结果。
- 复核状态机：没有完整材料或未完成复核不能标注通过，冲突交人工处理。
- 财务数值规则：补齐原始字符串精度、舍入、币种、期间和不可比口径处理。
- 质量评测：建立人工核验样例，覆盖缺失、歧义、冲突与注入；比较单 Agent 和多 Agent 的正确性、延迟、费用。
- 服务保护与部署：全局准入、限流、任务超时、预算、TLS、生产构建、秘密管理和回滚。
- 备份与恢复：验证图状态和目录部分失败时的协调及恢复，不将分库操作视为原子事务。

## 产品能力

- 完整财报接入、表格与必要 OCR 解析；保留页码、解析版本与明确失败状态。
- 来源与更正版本管理，区分报告期、公告日期、币种和报表口径。
- 跨期、跨公司比较，明确不可比项目，不把缺失当零。
- 研究底稿导出，保留证据、公式、结果、复核状态和数据版本。
- 基于检索基线评估全文索引、混合检索及重排序，不预设向量检索一定更好。
- 人工反馈闭环、远程提示词管理与自动评测。

## 生产观测与扩容

Langfuse Callback 追踪代码与离线集成检查已实现，远程项目部署、真实供应商流式 usage、价格匹配与账单校准需按环境验收。后续补齐采集健康监控、数据版本关联、失败补偿、权限和保留策略及质量/费用告警。

出现实际容量需求后，再评估共享执行所有权、跨实例停止、服务端数据库与长任务调度。验收同会话并发、实例失联、重复执行及恢复行为后才能多实例部署。

准确率、SLO、容量、恢复目标和成本预算需基于实测确定，不提前声明未经验证的指标。
